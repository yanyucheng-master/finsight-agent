## 本机大模型调用排查（2026-10-28）

用户写入 Key 后首次运行失败。`scripts\diagnose.bat` 的结果：
- **根本原因**：脚本找到的 Python 是 `AppData\Local\Programs\Python\Python314`（3.14.5），里面没装 fastapi / httpx / pydantic 等依赖，程序在导入阶段就退出了。已新增 `_deps.bat`：首次运行时自动 `pip install -e backend`，PyPI 失败时改用清华镜像，日志写入 `data\runs\pip_install.log`。
- **Key 和网络都正常**：两个 Key 格式无误；DeepSeek 与 Kimi 的 `/models`、对话接口都返回 HTTP 200。可用模型：DeepSeek `deepseek-flash`、`deepseek-v4-pro`；Kimi `kimi-k3.1-pro`、`kimi-k3`、`kimi-k2.6` 等。
- **空回复**：诊断用 `max_tokens=10`，两家都返回 200 但回复为空。原因是两家都是推理模型，思考内容也计入 max_tokens，还没开始作答就被截断了。
- 按官方文档又查出两处**依赖装好后也会失败**的兼容问题，已修复并加了测试：① DeepSeek 思考模式在带工具的多轮对话中必须回传 `reasoning_content`，否则 400（智能体会在第二步失败）；② Kimi K3 系列的 temperature 固定为 1.0，传其他值会报错（原来固定传 0.2）。
- Kimi 默认模型改为 `kimi-k3.1-pro`：较新，第三方资料显示单价更低、事实错误率更低（价格以官方控制台为准）。

**待用户本机运行** `scripts\llm_smoke.bat`（自动装依赖 → 两家连通性与工具调用往返 → 3 份简报 → 2 个问答），结果写入 `data\runs\`，再 stage 回容器复核。

## 重要发现：数据源保存的是“追溯调整后”的历史数据

东方财富的历史年度数据会在公司追溯调整后被更新：例如康美药业 2017 年货币资金显示为 42.07 亿元，更新日期为 2019-04-30，即会计差错更正公告之后；康得新 2015–2018 年数据统一更新于 2021-02-28。
**用这类数据回测历史造假案例会产生“未来信息泄露”**，命中率会被高估。因此：
1. 回测必须使用原始披露数据，即从巨潮原始年报 PDF 中抽取关键科目，并记录页码溯源；
2. 可以把“`UPDATE_DATE` 远晚于 `NOTICE_DATE`”与“会计差错更正”公告关联起来，作为一条治理风险信号；会计政策变更等正常调整要排除在外。
