# FinSight Agent 设计文档

## 1. 产品定位

**可追溯的上市公司投研智能体**：报告里的每个财务数字都关联到证据，计算过程可以逐步复查。交付范围与验证记录见 `STATUS.md` 和 `RELEASE-20261103.md`。

参赛赛题「AI+金融赋能应用赛」要求“依托人工智能技术改造金融业务流程，面向客户服务、投研分析场景构建智能化解决方案”。
本项目改造的是**投研分析流程**：取数 → 数据核验 → 指标与模型 → 风险排查 → 撰写简报 → 人工复核。问答智能体可延伸到客户服务（投顾解读）场景。

- **用户**：证券研究员、投资经理、信用 / 风控分析师；进阶个人投资者。
- **核心问题**：财务研究要读大量报表、附注、公告，交叉比对耗时；通用大模型问答很快，但会编造或算错数字。
  本项目用自有样本的三组对比与财报抽检来衡量数字的可追溯性。
- **价值主张**：既有 AI 的速度，又有审计的严谨。系统自动完成“取数 → 核验 → 指标 → 风险排查 → 解读”全流程，
  并把每一个数字的证据链交给用户检查。

### 与现有方案的差异

| | 金融终端（Wind/iFinD） | 通用大模型 + 数据插件 | FinSight |
|---|---|---|---|
| 数据 | 全，但要人工分析 | 由模型转述，可能出错 | 原始响应快照 + 哈希，可回放 |
| 计算 | 人工 / 公式 | 模型“心算” | 确定性引擎，公式与输入全程登记 |
| 风险识别 | 需要专家经验 | 泛泛而谈 | 文献模型 + 经验规则，阈值、依据全部公开 |
| 可信度 | 依赖使用者 | 不可审计 | 证据账本 + 数据核验 + 结论核验 |

## 2. 核心场景（按优先级）

1. **财务风险体检**：输入代码，约 1 秒得到六大维度信号、三大预警模型、数据核验报告，所有数字均可溯源。**已实现（确定性部分）。**
2. **可验证 AI 研报**：大模型只依据证据清单（E1..En）撰写解读，每个数字都必须引用编号；核验器逐条比对，不合格的数字会被打回修订一次，仍不合格则在文中标红。**已实现。**
3. **研究问答（智能体）**：自然语言提问，智能体在有限步数内调用 8 个确定性工具（指标、科目、信号、模型分解、公告检索、数据核验、同业比较、指标目录），给出带引用的回答，并展示工具调用轨迹。**已实现。**
4. **同业对比、公告事件雷达、历史案例回测**：*后续阶段。*

## 3. 架构

```
React 前端（工作台：体检 | 财务数据 | 研报 | 问答 | 溯源抽屉）
        │ REST / SSE
FastAPI ─┬─ 体检工作流（确定性，无 LLM）── analytics/diagnosis.py
         ├─ 可验证简报（证据清单 → LLM 撰写 → 核验 → 修订）── reporting/report.py
         └─ 研究智能体（LLM 工具调用，步数受限）── agent/research_agent.py
              │        大模型网关（OpenAI 兼容，适配推理模型）── llm/gateway.py
              │
  ┌───────────┼──────────────────────┬──────────────────┬─────────────────┐
  数据层        标准化                  计算引擎             证据账本            核验
  collector    schema.py 科目表         engine.V（依赖追踪） ledger.py          checks.py 数据核验
  snapshots    eastmoney.py 解析        metrics / models    （事实→指标→信号）  verifier.py（LLM 结论核验）
  service      CompanyData             rules.py 风险信号
```

### 关键设计决策（ADR）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **大模型不产生数字**：数字只来自确定性引擎；LLM 负责规划、解读、写作，并引用证据 ID | 从流程结构上约束数字来源，并由核验器逐个复核 |
| 2 | **工作流 + 智能体混合**：体检走固定流程；开放问答走受限工具调用；不引入多智能体框架 | 可预测的任务用工作流更可靠、更便宜，系统也更容易测试 |
| 3 | **原始响应内容寻址快照**（SHA-256），分析只读快照 | 可复现、可离线演示、可审计；云端开发环境无法访问国内数据源 |
| 4 | Python 3.10+ / FastAPI / Pydantic；前端 React + TS + Vite；不用 LangChain | 金融数据生态以 Python 为主；轻依赖，控制力强 |
| 5 | 大模型网关兼容 OpenAI 协议：测试用 DeepSeek（`deepseek-flash`），参赛用 Kimi（`kimi-k3.1-pro`，以官方文档为准），也可切换书生等 | 成本可控、支持工具调用；无 Key 时降级为模板报告 |
| 12 | 网关按模型族适配推理模型：发送 `reasoning_effort`（默认 low）；Kimi K3 系列不发送 temperature 等固定采样参数；多轮与工具调用时原样回传 `reasoning_content`；max_tokens 按推理模型放大；“200 但正文为空”视为截断错误 | 本机首次实测：max_tokens 过小时两家都返回空回复；查阅官方文档发现 DeepSeek 带工具时不回传思考内容会 400、Kimi K3 传 temperature 会报错 |
| 10 | 阈值和模型参数也登记为证据（`p:`），报告里的阈值数字同样可引用、可核验 | 实测发现“低于 1.10”这类阈值数字会被核验器判为无证据 |
| 11 | 回测必须使用原始披露数据，不能直接用数据源的历史值 | 数据源保存的是追溯调整后的数据，直接回测会泄露未来信息 |
| 6 | 金额统一用“元”，比率用小数；展示层再换算 | 避免单位混乱，这是核验器能逐字比对的前提 |
| 7 | 金融类公司（银行 / 保险 / 证券）不套用工商业指标，统一标记“不适用” | 报表结构不同，硬套会得出错误结论 |
| 8 | 重要性原则：应收等科目规模不重要时，DSRI 取中性值、应收增速规则不触发，并在证据中披露 | 实测发现茅台因票据重分类导致 DSRI 被放大、误报高风险，据此修正 |
| 9 | 公告事件只基于标题识别，过滤“专项说明 / 汇总表 / 制度”等例行披露 | 实测例行的“资金占用专项审计报告”导致大面积误报 |

## 4. 数据源与合规

| 来源 | 内容 | 获取方式 | 成本 / 授权 | 状态 |
|---|---|---|---|---|
| 东方财富 F10（公开网页接口） | 三大报表、主要指标、公司概况 | 采集器限速抓取 | 免费；仅用于非商业研究 / 竞赛原型，遵守站点条款，不转售 | ✅ 已接入 |
| 巨潮资讯（证监会指定披露平台） | 代码表、公告列表、年报 PDF | 同上 | 免费公开 | ✅ 已接入 |
| 东方财富行情 / K 线（push2） | 市值、历史价格 | 同上 | 免费 | ⚠️ 对方断开连接，待修复或换源 |
| 同花顺 iFinD MCP / 东方财富妙想 Skills / Tushare | 机构级数据 | API Key | 需授权或付费，**未经用户同意不接入** | 规划中的可插拔适配器 |

- 采集器只用标准库，在用户本机运行（云端开发环境的出网白名单不含国内数据源）。
- 每次请求都记录 URL、参数、UTC 时间、HTTP 状态和 SHA-256；读取时重新校验哈希，可以发现文件被篡改。
- 每个事实都带有 `notice_date`（公告日期），回测时用于避免未来函数。

## 5. 可靠性设计（三道防线）

1. **数据核验**：会计恒等式 11 项、平衡项、跨期连续性，以及与数据源发布指标的交叉核验（毛利率、净利率、资产负债率、流动比率、速动比率）。
2. **计算可追溯**：`V` 类型在四则运算中自动合并依赖；缺失值和除零都显式标注，缺失值保持为空，不以 0 填充。
3. **结论核验（已实现）**：抽取 LLM 文本中的数字与引用，逐条与证据比对，比对时做单位换算、容差和期间一致性检查；不合格时回传给模型修改一次，仍不合格就删除或标红。报告给出“可核验率”。

## 6. 风险方法论

- 指标 30+，覆盖盈利能力、盈利质量、成长、偿债、资产质量、营运六类；三大模型为 Beneish M-Score、Altman Z''、Piotroski F-Score。
  口径与本地化处理详见 `backend/finsight/analytics/{metrics,models}.py` 的文档字符串。
- 每条信号标注阈值类型（文献 / 经验 / 事实）并附依据，用于确定核查重点，最终判断由研究员结合附注完成。
- 综合评级规则公开：核心维度出现高风险信号，或高风险信号 ≥2 → 高；出现任一高风险信号，或中风险信号 ≥3 → 中；其余 → 低。

## 7. 前端（2026-11-04 重做）

研究工作台，视觉与大师实验室同一套浅蓝玻璃体系（墨蓝正文、主蓝强调、大圆角卡片），风险配色遵循 A 股“红高绿低”的约定。
动效只表达真实发生的事：点击、数据到达、核验结果、服务端回报的生成阶段；不做假进度，表格里的财务数字不做滚动动画；系统开启“减少动态效果”时只保留内容。

- 首页：搜索（代码 / 名称 / 拼音，键盘可选）+ 证据链示意（数值取自快照）+ 汇总条 + 样本公司卡片（评级、核验通过数、八维度风险竖条）。
- 公司工作台：评级三段弧 + 汇总指标｜风险体检（维度雷达 + 信号卡 + 模型分项）｜研究简报（引用标签 + 核验环形图）｜智能问答（工具调用轨迹）｜指标趋势｜财务报表（点击单元格可溯源）｜数据核验。
- 溯源抽屉：证据 → 公式与代入算式 → 证据链逐节点 → 原始字段 → 快照（URL、抓取时间、SHA-256，可复制）。
