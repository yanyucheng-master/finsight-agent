## P1：数字提取真实漏检，正负号错误可能被判通过

`backend/finsight/reporting/verifier.py` 的 `NUM_RE` 使用 `(?<![\w.])`；Python Unicode 中汉字属于 `\w`，数字紧贴汉字时不能从数字开头匹配。真实报告 `report_600519.json` 正文有远多于 9 个数字，但 `claims` 只捕获 9 个。将其中 `毛利率为91.18%[E17]` 替换成 **`毛利率为99.99%[E17]`**，`verify` 仍返回 passed=True、9 个断言；仅在错误数字前加空格才会检出 mismatch。文件 `verify_regressions_oct30.py` 可使用项目虚拟环境离线复现，无 API 调用。

合成证据值为 -12.30% 时，`增长率为 +12.30%[E1]。` 也被判 verified/passed；`_matches` 容许绝对值相等并认为正负由文字表示，但这里存在明确的相反符号，且没有“下降”等语义。无空格时还会丢掉正负号。例如真实报告中的 `为-1.21%` 被提取为 `1.21%` 后，借助绝对值匹配标记 verified。应覆盖中文紧邻数字、带符号、千位分隔符、引用、多段文本、正确与错误符号等场景；不应把“允许下降 12% 对应负值”泛化为所有符号颠倒都可接受。当前离线注错评估的高检出率不足以证明真实中文排版的覆盖率。

## P1：中文紧邻千分位导致误报

`report_600518.json` 中 `2025年归母净利润为1,032.80 万元[E3]` 数值与 E3 一致，但核验器从逗号之后开始捕获 `032.80 万元`，标为 mismatch，导致一次模型修订后仍然失败。这与上述数字边界问题相关；修复时应同时检查漏检和误报，勿单纯关闭核验。

## P1：预算保护不能作为严格逐请求预留

`gateway.py` 在重试循环外只调用一次 `BUDGET.reserve`，网络异常/超时后没有把上一次可能已由服务端计费的请求按预留额记账，就继续重试。离线 `httpx.MockTransport` 复现：首次 ReadTimeout、第二次成功时有 2 次发送，预算只记录 1 次成功调用。并发下 `reserve()` 不占用余额也不与 `charge()` 同锁，多个请求也可能各自通过相同剩余额度。`chars` 近似 token 并非严格上界；未知模型的回退价格也不能保证实际单价不高于估算。请区分“客户端估算”和服务端硬限额，超时不明费用按保守上界记账，逐次重试及并发需原子预留；预算不明确时应停止。

## P2：时效信息仅放进提示词，未保证实际输出

`data_asof()` 只注入 LLM 上下文，LLM 最终回答没有确定性追加所有元数据。第二轮 600519 简报只写“截至2025年年报”，既无公告日、采集日，也无“不能代表之后最新情况”；000002 简报无公告日和采集日；600518 无公告日和采集日。两个问答都注明年报口径与非最新状况；万科问答有公告日，但无采集日。建议在服务端生成可验证的元数据说明，而非依赖模型选择是否输出。对于多源、不同时期和多公司，不应把任意一条证据来源日期误表述为全体证据的唯一公告日。
