# 路线图（截至初赛 2026-11-05）

原则：先打通可验证的主链路，再叠加 AI 能力，最后打磨演示与材料。每个阶段都有可测试的验收标准。

| 阶段 | 日期 | 内容 | 验收标准 | 状态 |
|---|---|---|---|---|
| M0 基础 | 10-27 | 赛事核对、架构设计、采集器、快照仓库、标准化、指标 / 模型 / 核验 / 规则引擎、CLI、API 骨架 | 10 家样本真实数据跑通；恒等式与交叉核验全部通过；测试通过 | ✅ |
| M1 数据补强 | 10-28 | 修复银行类 companyType（采集器 v0.1.1 已改，需重采）；行情 / 市值换源；扩充样本（含同业、近年处罚案例）；年报 PDF 解析（审计意见、受限资金） | 银行三表齐全；市值可用于原版 Z-Score；样本 ≥ 30 家 | ⏳ |
| M2 AI 层 | 10-28~10-30 | 多供应商 LLM 网关（**书生**为参赛主模型，前提是确认参加书生赛题；DeepSeek 用于低成本测试；Kimi 作备选/对照）+ Mock；带引用的研报生成；**结论核验器**；受限工具调用问答智能体；SSE 进度 | 研报中可核验数字占比 ≥ 99%；未核验数字必定被标出；Mock 测试覆盖修订循环 | ⏳ |
| M2.5 生态封装 | 10-30 | 把取数、指标、核验、证据查询封装为 **MCP 服务** 与 **Agent Skills**（评分“前沿技术应用深度”） | 在 MCP 客户端中能调用并返回带证据 ID 的结果 | ⏳ |
| M3 前端 | 10-29~11-01 | 工作台四个主页面 + 溯源抽屉；后端托管构建产物；`start.bat` 一键启动；**公开部署，作为“应用体验链接”** | 本机与公网链接均可端到端演示；Playwright 冒烟测试通过 | ⏳ |
| M4 评测 | 10-31~11-02 | ①数据核验通过率；②数字幻觉对比（纯 LLM vs FinSight，问题集 + 标准答案自动生成）；③历史造假案例回测（处罚前年报，对照组）；④耗时 | 评测脚本一键复现，并生成评测报告 | ⏳ |
| M5 材料 | 11-02~11-04 | 按赛题文档要求：技术文档 PDF（内附 ≤5 分钟、≥720P 视频的网盘链接和应用体验链接）；关键代码 zip；总包按“单位简称-作品名称-队长姓名-队长手机号-日期.zip”命名 | 材料齐全，复核无误 | ⏳ |
| 缓冲 | 11-05 | 打包提交 | — | — |

## 任务依赖

- M2 依赖用户提供 DeepSeek API Key，**真实调用只能在用户本机进行**（云端开发环境无法访问模型 API）。
- M4-③ 回测依赖 M1 扩充样本：处罚案例名单必须引自证监会公开的行政处罚决定书，不编造。
- M5 依赖官方赛题细则（见 COMPETITION.md 待确认项）。

## 延后（初赛之后）

同业分位对比、公告全文理解（问询函要点抽取）、持续监控与预警推送、报告导出 PDF / Word、iFinD / Tushare 适配器、多用户部署。
